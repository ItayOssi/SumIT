# SumIT

Study app for HIT students. The UI is Hebrew and RTL.

## Layout
- `src/*.cs`: the Windows app (C#, WebView2). These files use CRLF line endings; keep them.
- `macos/`: the macOS Electron port. `macos/lib/modules/*.js` mirror `src/*.cs` one-to-one (each file says which C# file it ports).
  A logic change goes into both, with a test in both `macos/scripts/offline-tests.js` and `tests/RegressionTests.cs`.
  macOS-only features have no C# counterpart: flashcards, the quiz next to them (`quiz.js`: multiple choice, true/false and fill in the blank in three AI passes, kept as `בוחן.json` next to the summary; every answer is checked on the page by `src/web/quiz-core.js`, shared with the host, with no AI call; the UI is the "בוחן" tab of the cards column, `src/web/quiz.js`), spaced repetition (`reviews.js`), the pomodoro system alert (`pomodoro.js`), calendars (`calendars.js`), "I'm stuck" (`coach.js`) and "what to do in this block" (`block-plan.js`) and the study track, beta (`study-track.js`: a first-run wizard in `src/web/track-wizard.js`, a full screen like the setup wizard, that asks about the student's routine and reads the connected calendars from now on only (weekly commitments of the next four weeks, and busy one-time events of the next two, kept with their date), courses with a difficulty and an energy, a strategy per course, study tasks read from the course folders, a traffic light of the topics of each course before an exam (green known, yellow needs work, red not known: set by the student, suggested from the lectures and from the syllabus, which a helper AI reads once into `.sumit-topics.json` in the course folder; the last quiz and the cards failed twice only suggest a change; red topics give Feynman goals and yellow ones recall goals, before the lectures; green counts as a topic finished; a card "לקראת המבחנים" on the overview shows the colors of each exam and the topics that got better in a week, two weeks before an exam a quick round rates the topics one at a time, and "I'm stuck" (`coach.js`) starts from the easiest yellow topic), a week of blocks whose goals are study methods on that material (one per lecture of the four newest, in an order set by the kind of course: the Feynman technique, exercises from the practice sheet, the quiz of the summary, recall on a blank page; the cards due as one review goal, or at the end of the first block when fewer than 15; a goal done this week is not given again when the week is built again; never making a summary), and the tasks card shows one task of each kind per course and nothing the week already has as a goal that puts heavy courses in the hours of most energy, progress kept in a local profile file with export and import, and a streak as in Duolingo: a day counts when a block or a topic was finished in it, a freeze earned every 7 days covers a missed day, a celebration when the flame lights and an evening reminder at 20:00, and sparks (✨) with achievements: `sparksInfo` in `study-track.js` counts them from the profile alone (10 a quarter of an hour of a block times its study method, from ×1 for cards to ×3 for a past exam, 30% more for a hard course, at most 600 a day of what is only reported; memory cards rated and quizzes finished, which the app sees, come through `TrackActivity` from `reviews.js` and `quiz.js`; the streak multiplies the day, ×1.1 from 3 days to ×2 from 30, and a broken streak starts again at ×1; a missed day that no freeze covers costs 20, for the first 5 days of a break, and the total never goes under 0; the streak card shows the last seven days with today last; levels; 15 achievements in three tiers, three of them hidden, each announced once), shown by `src/web/sparks-ui.js` with sounds made in Web Audio), and the study tools (`study-export.js`: the week's blocks as an iCal file, a folder of sources for NotebookLM, the cards as an Anki text file, the summary PDFs of a course to iCloud Drive `SumIT/<course>/Lecture_NN_<topic>.pdf` with a `metadata.json` for the iPad; they are buttons in the study track page), and the sync of the study blocks into the Calendar app of macOS (`calendar-sync.js`, with the script macOS runs in `macos/lib/scripts/calendar-sync.jxa.js`; the tests use a fake Calendar and must never reach the real one), and "המחשה חזותית" (`visual.js`: a button on each homework question of a summary, added to the page when it is shown by `src/web/study-viz.js`; a helper AI gets only the question and answers with a short JSON spec that `src/web/viz-runtime.js` checks and draws (plot, wave, circuit with mesh-current loops and colored equations, field3d, or a small custom HTML; a "board" style looks like a blackboard) in a sandboxed frame with no network, styled by `src/web/viz-frame.css`; kept in `.sumit-viz/` next to the summary), and the sync with Google Drive (`drive-sync.js`, card in `src/web/drive-ui.js`: sign-in with Google through the browser, PKCE and a 127.0.0.1 redirect, scope `drive.file` only; the study folder mirrored into a "SumIT" Drive folder (without the work folders `.sumit/work|scratch|tmp`, whose copies already in Drive are left there and forgotten; four files move at a time), a three-way compare with the state of the last sync in `drive-sync.json`, both versions kept on a conflict, deletes to the Trash, a stop before mass deletes, and the settings without keys or folders; sign-in also asks for `profile`, and the first one fills an empty name and picture from the Google account, and "switch account / update from Google" in the profile signs in again and replaces them (the previous permission is revoked); the settings that travel include the student's tasks, and the profile picture travels as `.sumit/profile.jpg` named by its md5 in `settings.photo`; it is connected from the setup wizard (a step shown only when the host answers) or from the profile, opened by a click on the picture, which has a ring for the state of the sync; the client id is in `constants.js`, the client secret comes from `SUMIT_GOOGLE_CLIENT_SECRET` or `macos/lib/google-oauth.json`, which the release workflow writes from the repository secret `GOOGLE_OAUTH_CLIENT_SECRET`; the tests use a fake Google and never reach the real one)., and the friends leaderboard (`leaderboard.js`, tab "חברים" of the study track in `src/web/board-ui.js`: a group with a 6-letter code, ranked by this week's sparks; Firestore of a Firebase project through REST, signed in with the Google id_token of the Drive connection; `C.Firebase` in `constants.js` holds the public apiKey and projectId, and while they are empty the tab stays hidden; the rules and the setup steps are in `macos/firebase/`; a member writes only their own row (name, Google picture, week sparks, total, level, streak) and only members read a group; the groups travel with the settings as `boardGroups`; the tests use a fake Firebase and never reach the real one), and the reminder of the tasks ticket (`task-reminders.js`: the page sends the items due in the next two days, and from 09:00 each one due tomorrow gets one system notification; what was said is kept in `task-reminders.json` as "id|date"; the ticket itself, `src/web/tasks-ticket.js` and `tasks-ticket-ui.js`, is shared and needs no host), and notes from a live call (`live-notes.js`, card at the top of a course's "הקלטות" tab and a bar on screen while recording in `src/web/live-notes-ui.js`: for a call with no Zoom recording; the helper `macos/native/sumit-audio.swift`, built into `macos/bin/sumit-audio` by `scripts/build-audio.sh` and shipped in Resources/bin, hears the Mac's output through a Core Audio tap (macOS 14.2+) and the microphone, mixed into FLAC parts of four minutes in `.sumit/work/live/<id>`; each part goes to Gemini Flash with the student's key as soon as it closes, one more call writes the notes, the page is saved in `<course>/שיחות/`, and then the audio and the text are deleted; on a failure they stay for "נסה שוב", and are deleted after a week; the tests use a fake recorder and a fake Gemini and never reach the real microphone), and the lecturers' announcements (`moodle-news.js`, UI in `src/web/moodle-news-ui.js`: a card at the top of the home pane "מה מחכה לי" and a banner in a course; every two hours, in the student's Moodle session, the announcements forum of each course that is set up (picked from the cached sections by its name, "לוח הודעות") is read from the forum page, since HIT closes the forum web services except `mod_forum_get_discussion_posts`, which gives the text of a new one (the discussion page is the fallback); the first read only remembers; words sort each new one into cancel, change, exam or general, and only when they don't decide and a date, an hour or a room is mentioned does a helper AI with a key get that one announcement; cancel, change and exam get a system notification; kept in `moodle-news.json`; the tests use a fake Moodle and never reach the real one), and the logos of the institution picker (`inst-logos.js`: the real logo, from the address in the list (the institution's page on the Hebrew Wikipedia or its own site), read the first time and kept in `inst-logos/`; the site's icons are the fallback, and the page shows the initials badge until then). The institution itself (`src/web/institutions.js`: about 30 institutions in Israel with their Moodle and portal; `macos/lib/institution.js` keeps the one in use, and every Moodle/portal check goes through it; the picker is `src/web/institutions-ui.js`, step 2 of the setup wizard and a card in the settings) is shared; a student without a saved institution stays at HIT. Their UI is in `src/web/` and stays hidden on Windows until the host answers.
- `src/web/`: the web UI shared by both apps.
- The summary dialog (`requestLectureSummary` in `src/web/app.js`): buttons above the notes (`SUMMARY_PRESETS`) write fixed lines into the notes, which reach the AI as they are. Once a lecture has a summary, "סיכום נוסף" builds another one with its own name and notes in `סיכום הרצאה/סיכומים נוספים/<name>/` (with `מיקוד.txt`), never replacing the main one or its notes, with no digest, pointers or second opinion (`ExtraSummaryAsync` in `lecture-pdf.js` / `LecturePdf.cs`).
- `src/web/splash-poster.js`: a limited-time poster splash (until 1 Dec 2026), with original art in `src/web/images/poster/`. The word "SumIT" there is a fixed image in Pricedown: the font file itself must never be added to the app (its free license covers static artwork only).
- `src/web/vendor/fonts/`: Hebrew fonts kept in the app (the page's CSP loads nothing from the network), Hebrew and Latin subsets with their OFL license, declared in `fonts.css`: Heebo, Rubik, Assistant, Noto Sans Hebrew, Varela Round, Frank Ruhl Libre, and for titles only Secular One, Suez One, Karantina. The fonts are chosen by three tokens at the top of `style.css`: `--font-ui` (the whole app, Rubik), `--font-display` (titles, Rubik) and `--font-practice` (the cards, the quiz and the daily review, Heebo). Name a font through a token, never directly. A summary page is in Assistant with Rubik titles: `study-book.css` declares them, and `AddBookLayout` (`summary-book.js` / `SummaryBook.cs`) copies their folders into `.sumit-math/fonts/` next to the page, so it needs no network and a shared ZIP carries them.
- Emojis are Fluent Emoji (Microsoft, MIT) in `src/web/vendor/emoji/` (`flat/`, and `3d/` for the big moments): the app draws them with `emo()` / `setEmo()` from `src/web/emoji.js`; a summary page draws them with the `.sb-emo-*` classes of `study-book.css` (set by `study-book.js`), and `AddBookLayout` copies them into `.sumit-math/emoji/`.
- `docs/`: screenshots and release notes (`release-<version>.md`, in Hebrew).

## Checks (from `macos/`)
- `npm install` once, then `npm test`. Expected: `38 Host mixin modules loaded cleanly` and `ALL 744 OFFLINE REGRESSION CHECKS PASSED` (update the count when tests are added).
- Needs Node 23 or newer: `macos/lib/modules/summary-share.js` uses a regex with duplicate named groups. On Node 22, run the scripts with `node --js-regexp-duplicate-named-groups`.
- The C# code can only be built on Windows.

## Run and build (macOS only)
- `npm start` runs with the real accounts; `npm run demo` runs without Moodle or AI.
- `npm run dist:arm64` builds `macos/dist/SumIT-<version>-arm64.dmg` and `.zip`.

## Releases
- Bump the version in `macos/package.json` and `macos/lib/constants.js`, add `docs/release-<version>.md` in Hebrew, and add a line at the top of the README.
- Release tag `v<version>-mac` on `ItayOssi/SumIT`, with the DMG and the ZIP attached. Pushing the tag (`git tag v<version>-mac && git push origin v<version>-mac`), or running the "Release macOS" workflow by hand on `main` (it then creates the tag), runs `.github/workflows/release-mac.yml`: it tests, builds on a GitHub Mac and publishes the release with `docs/release-<version>.md` as the notes. The app's automatic update reads these releases.

## Rules
- Push only to `ItayOssi/SumIT` (the user's fork). Never push to `Pinkel-Kinkel/SumIT`.
- Write release notes and messages to the user in Hebrew.
